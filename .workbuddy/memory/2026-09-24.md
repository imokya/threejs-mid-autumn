## 同一场景：加载慢 / 卡顿优化

用户反馈「打开极慢，还卡顿」。分析出的根因与处置：

- **最大浪费**：`makeTextures()` 里程序生成 2048×1024 月面（逐像素 fbm 噪声 + 1800 陨坑 + `filter='blur(5px)'`）约 65% 的纹理耗时，紧接着就被 NASA 影像 `dispose()` 替换。
  处置：抽成 `drawProceduralMoon(g, w, h)`，`makeTextures()` 里只 `canvasTex(256, 128, drawProceduralMoon)` 占位；仅当影像加载失败才全分辨率生成。
  **关键技巧**：`mulberry32` 加了 `state()/set()`，兜底生成后 `rand.set(seedAtSceneStart)` 把随机流拨回，因此场景（林木/山石/灯影）的随机细节与优化前完全一致。另外程序月面的 R() 调用数只与循环次数有关、与 w/h 无关，所以小画布空跑消耗的随机数完全相同。
- `makeTextures()` 改 `async`，在 4 处分批 `await nextFrame()`，片头 loader 不再整段卡死。
- `noise2()` 每采样点原本调 4 次 `Math.floor`，改为复用取整结果（输出完全一致）。
- 新增 `TUNE` 画质档位 + `?quality=low|high` + `?stats`（左上角 FPS/档位/后端/像素比）+ 像素比自适应（fps<48 连续 2 秒降 0.25，>57 连续 4 秒升回，下限 1.0）：
  像素比上限 2→1.75（低档 1.0）、MSAA 4→2（低档 0）、阴影 2048→1536（低档 1024）、水面反射 0.5→0.4（低档 0.3）、阴影每 2 帧刷新（低档每 3 帧）。
- **踩到的坑（重要）**：three r180 的阴影走 `ShadowNode`，刷新闸门是 **`light.shadow.autoUpdate/needsUpdate`**；`renderer.shadowMap.autoUpdate` 在 build 里 0 次引用，设了没用。`renderer.shadowMap.type/enabled` 仍被读取。
- **另一个坑**：WebGPU 的 `sampleCount` 只接受 1 或 4（three 直接写进纹理描述符），`pass(...,{samples:2})` 在 WebGPU 后端会 validation error；已按后端改成 0/2（WebGL2）、0/4（WebGPU）。
- `renderer` 的 `antialias` 改为 `false`：抗锯齿由后期 `pass()` 的 MSAA 负责，最终只是一张全屏四边形，画布再留多重采样缓冲是浪费。
- 去掉每帧冗余的 `boat.updateMatrixWorld(true)`（`getWorldPosition` 内部已更新祖先链）。
- 尾部加 `phase()` 计时表（console.table，含首帧渲染/着色器编译），便于用户自己回报瓶颈。

## 同一场景：第二轮帧率优化

- **约束（务必记住）**：场景里所有 `R()`（mulberry32 随机流）的**调用顺序**决定了林木/山石/灯影的位置。任何新增/删减循环次数或调整 R() 调用顺序的改动，都会让整片场景的随机细节错位。本轮所有减面改动都采用「随机数照常按原顺序抽完，只是条件性跳过造面片」的写法（云 `clouds.length >= TUNE.cloudCount`、雾 `i >= TUNE.mistCount`）。
- **水面反射隔帧复用**：挂在 `reflection.reflector.updateBefore`（ReflectorBaseNode，`bounces:false` → `updateBeforeType = FRAME`）。节拍由主循环 `frameNo` 驱动。
  - **坑**：跳过时必须返回 `undefined` 而非 `false`。three 的 `updateBeforeNode` 逻辑是 `if (node.updateBefore(this) !== false) frameMap.set(reference, frameId)` —— 返回 `false` 会被判为「本帧没执行」，同一帧的下一个绘制对象会再调一次。另外一帧内 `renderer.render()` 会多次调用并各自 `frameId++`，所以不能用「数 updateBefore 调用次数」来算节拍，必须用主循环的帧计数。
- **程序噪声降阶**：云 5→3、雾/贴水薄雾/远山 4→3、云海 5→3；「过月之云」单独保留 5 阶。依据：fbm 振幅序列 1,0.5,0.25,0.125,0.0625 的标准差是 1.154/1.152/1.146/1.118，去掉最高阶只让标准差变 0.15%~0.7%，视觉上只在 `smoothstep` 过渡带里产生极轻微的软化，却省掉这些着色器四成运算。`cloudMaterial` 加了 `oct` 参数。
- 阴影 1536→1280 且每 3 帧（低档 896 / 每 4 帧）；反射分辨率 0.4→0.32（低档 0.3→0.24）。
- 低档减面：雾 34→20、云 9→6（只影响低档，高档画面构成不变）。
- 砍掉 `poet.root.updateMatrixWorld(true)`：`getWorldPosition/getWorldQuaternion` 内部走 `updateWorldMatrix(true,false)`，会自行沿父链用**当前**局部矩阵重算，所以那份显式刷新是重复劳动。
- 像素比自适应：取样窗口 1s→0.7s，升档需连续 6 窗口稳定，下限低档 0.85。
- `?stats` 面板升级为两行：FPS/档位/后端/像素比 + `CPU x.xms/帧 · N 绘制 · Nk 三角`。用 `renderer.info.autoReset = false` + 主循环里手动 `info.reset()`，这样一帧内主通道/反射/阴影/泛光的绘制次数是累加的真实总数（`Info.update()` 每次 draw call 调一次，`reset()` 清 `drawCalls/frameCalls/triangles`）。
- 新增 `?lights=lean`：跳过两岸民居 6 盏点光（全场点光 19→13），作为「光照循环代价」的 A/B 工具，默认不开（会压暗两岸暖光）。
- 未动手的后续杠杆：点光减盏、花瓣/河灯矩阵搬到顶点着色器、船体静态部件按材质合并减 draw call。

## 第三轮：画面调整（提亮 / 取景 / 飞鸟 / 减模）

用户四项诉求：建筑提亮、镜头不给东坡正面、加飞鸟、远景减模。均只改 `src/main.js`，未起服务实测（按用户规矩只做 `node --check`）。

- **建筑提亮**：新增 `ARCH` 表（17 种建筑材质），遍历施加 `color.multiplyScalar(gain)` + `m.emissiveNode = (m.map ? texture(m.map).rgb : color(base)).mul(glow)`。gain 1.18~1.70、glow 0.048~0.105。选 `emissiveNode` 而非加灯，是因为它是自发光项、不进光照循环、零额外开销。山水草木水面天空船体一律不动。参数集中成一张表，方便用户自己调。
- **取景**：写了 `/tmp/moonseq.mjs` 复现 `dir.blend` 混合状态机、逐帧（dt=1/60）复算 168 秒时间线，输出每镜东坡入镜情况与 `face` 值。结论：只有「起舞弄清影」切镜瞬间越到侧面（face≈-0.09），因上一镜在雷峰塔（他正面侧）。改用 `behind()` 背面取景后 face≈-0.76。
  - 新增 `guardRear()`：每帧把 `PB + (0, 0.9, 0)` 投影到 NDC，若东坡在画面内（|x|,|y| < 1.15 且 z<1）则算 `face = 归一化机位方向 · PF`（水平分量），`face > -0.25` 且该镜未告警过就 `console.warn` 点名。`dir.free` 或距离 <0.5 跳过。
  - `?stats` 第三行显示守卫读数。
- **飞鸟**：`FLOCKS` 表 = `[只数, 圈心x/z, 半径rx/rz, 高度, 周期秒, 起始相位, 体型, 环绕方向]`，三群 4+3+2=9 只。第一群椭圆穿过月面视线，每圈横越一次月亮。**关键坑**：实例网格的 `positionNode` 拿到的是已乘实例矩阵的坐标（three 的 `setupPosition` 里 `positionLocal` 在 `instancedMesh(object).toStack()` 之后），拿它做顶点位移会把鸟撕开。故改为「身体 + 左右翼」三个 `InstancedMesh`，CPU 每帧写矩阵：`_bw.matrix.copy(_bd.matrix).multiply(_bwR.makeRotationZ(±f)).multiply(_bwS.makeScale(1-|f|*0.16, 1, 1))`。翼几何原点在肩，绕 Z 轴对称摆。材质 `MeshBasicNodeMaterial` + `0x0a0f1c` + `fog:false`，逆光剪影。
- **减模**：`makeRange` 的 segX/segZ：近山 340×140→280×112、远景山 260×60→130×32（原摘要里写的两个数是 260/60 与 200/120，实际代码里只存在 260×60 这一处远山 + 150×84 的中景山，中景保持）、夕照山 plane 200×200→160×160。远景林按半径 210 米分两级 LOD：圈内 `FOLIAGE_HI`（Icosa 1,1 = 80 面）/ 圈外 `FOLIAGE_LO`（Icosa 1,0 = 20 面，配新材质 `M.foliageFar`，无 flatShading）。用 `farAway(x,z) = (x-14)²+(z+6)² > 210²` 判定（圈心=舟行中心）。**随机数照常按原顺序抽完**，只条件性跳过造面片，近景细节不变。实测圈外占比：近山 45.3%、岸上 2.4%。
